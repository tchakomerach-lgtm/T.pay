# P056.3.1 — Temporal permission grant lifecycle API

## Scope
This brick closes the missing management surface in P056.3. It adds organization-scoped authenticated APIs for grant listing, creation, and revocation. It does not replace the shared identity/session validator or the shared authorization evaluator.

## API
- `GET /v1/education/permission-grants?actorId=<uuid>` — list current and historical grants in the authenticated organization.
- `POST /v1/education/permission-grants` — create a grant with actor, permission, optional RFC3339 validity window and mandatory reason.
- `PATCH /v1/education/permission-grants/:grantId` — revoke an active grant with a mandatory reason.

All routes require `security.manage`. Mutations additionally require a step-up organization session. Target actors must be active and belong to the same tenant and organization. Requests reject unknown fields and use the existing API Gateway idempotency reservation.

## Persistence and security
- Migration 123 adds immutable revocation actor/reason evidence.
- Reads and writes execute inside a PostgreSQL transaction after `SET LOCAL ROLE tpay_school_runtime` and tenant/organization GUC binding.
- RLS remains forced; runtime has SELECT/INSERT/UPDATE only and no DELETE.
- Grant creation, revocation, append-only API audit, and idempotency completion commit atomically.
- Grant history is retained; revocation sets `revoked_at`, `revoked_by` and `revocation_reason`.
- No generic School SSE event is emitted for security-grant changes, avoiding disclosure of authorization metadata to ordinary organization members.

## Acceptance gates
- Unit/HTTP tests for security.manage denial, step-up denial, unknown fields, malformed UUID/time windows, inactive/cross-org actor, create/list/revoke and repeated revoke.
- Live PostgreSQL 17 tests using a least-privilege runtime login with RLS and no BYPASSRLS.
- Rollback test proves grant, audit and idempotency all roll back together.
- `npm run check`, `npm run security:fortress`, `npm run test:postgres`, Web build, Android build, and exact-head CI.
- No merge or certification until all evidence is attached to the exact SHA.
