# L12.3 — Secret rotation, deployment serialization and incident routing

## Built
- Secret rotation evidence stores only a secret reference, version and digest metadata; secret material never enters PostgreSQL.
- Deployment lease locking serializes schema/deployment operations and permits takeover only after lease expiry.
- Incident routes support email/SMS/webhook/pager/internal-queue references without storing credentials.
- Incident delivery evidence has a route-scoped idempotency key.
- Failed or suppressed delivery remains operational evidence and never mutates financial truth.

## Togo/Africa operating profile
- Low-bandwidth incident delivery may prefer SMS or internal queue while webhook/email remain optional.
- Provider credentials stay outside the repository and enter only through the authorized secret boundary.
- Deployment locks prevent concurrent migration/release workers from applying schema changes simultaneously.
- Provider outages degrade to queued evidence and reconciliation, never silent ledger correction.

## Required exit evidence
1. Exact-head CI green.
2. PostgreSQL race test proving one live deployment owner per lock.
3. Migration checksum/ordering integrated with the deployment runner.
4. Authorized secret-provider rotation drill with old/new credential overlap and rollback evidence.
5. Incident routing integration tests with retry, deduplication and dead-letter handling.
6. L12 backup/restore/failover drills and named production owners.
