# L12.5 — Operational reconciliation and DR

This layer proves that degraded operation, provider mismatch and recovery drills become durable operational evidence without changing financial truth.

## Reconciliation domains
- Ledger/provider: compare provider evidence with Financial Core settlement state; ambiguous records remain quarantined.
- Offline: reconcile accepted device envelopes against server state and sequence/replay evidence.
- Cash: reconcile agent sessions and physical cash evidence; no automatic correction.
- Notifications: reconcile queued/sent/failed delivery evidence.
- Full: orchestrate domain checks with one correlation ID.

## DR
RPO/RTO are policy targets until an actual drill records observed values. Restore/failover/provider-outage/region-loss drills must run in isolated or authorized environments. A failed drill blocks production-readiness claims.

## Africa/Togo degraded mode
During provider or network outages:
1. preserve evidence/intents;
2. allow only explicitly safe offline operations;
3. queue SMS/internal-queue escalation;
4. reconcile after reconnection;
5. quarantine conflicts;
6. never synthesize Ledger entries to make dashboards look healthy.

## Exit gates
1. exact-head CI green;
2. PostgreSQL concurrent exception upsert/idempotency proof;
3. reconciliation handlers connected to provider/offline/cash queues;
4. restore and failover drills with observed RPO/RTO;
5. provider-outage drill;
6. named owners/escalation and low-bandwidth route;
7. dashboards show backlog, age, mismatch and quarantine counts.
