## Threat gate

| Risk | Control |
|---|---|
| provider spoofing | callback verification contract; live adapter must use signed verification |
| duplicate initiation/callback | idempotency key + provider event uniqueness at settlement |
| provider timeout | pending/unknown semantics; no automatic failed transition |
| retry creates second payment | same idempotency key; bounded retries; no blind retry of non-idempotent operation |
| circuit open hides money state | breaker controls new attempts only; reconciliation/query remains available |
| cross-org response | command carries organizationId; settlement verifies organization/payment identity |
| amount/currency mismatch | event validation before settlement; mismatch quarantine |
| adapter bypasses ledger | adapter interface exposes no ledger dependency |
| credential leakage | secrets stay in provider transport/secret store; no credentials in Git |
| denial of service | bounded retries, circuit breaker, rate limits at higher boundary |

## Acceptance

- registry rejects duplicate provider IDs;
- TMoney/Flooz/microfinance all implement the same contract;
- normalized statuses are explicit;
- correlation/idempotency are propagated;
- circuit breaker and bounded retry are deterministic;
- adapter contract exposes no ledger mutation;
- tests cover duplicate registration, pending semantics and transient/non-transient failures;
- CI green.

## Remaining risks

- live provider protocol schemas and credentials are not connected;
- signed callback parsing remains S-03.2;
- durable provider event claim remains enforced by S-02/S-02.5 settlement boundary;
- production circuit metrics/alerts are not wired yet.
