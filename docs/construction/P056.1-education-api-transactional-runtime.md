# P056.1 — Education API Transactional Runtime

## Scope
This sequence connects authenticated school class and enrollment operations to the existing PostgreSQL Unit of Work and durable transactional Outbox. It is additive on top of P056; it does not certify P056, P057, or P058.

## Runtime invariants
- POST /v1/education/classes, POST /v1/education/enrollments, and PATCH /v1/education/enrollments/:id use one checked-out PostgreSQL client.
- The transaction sets tpay_school_runtime locally and derives tenant/organization GUCs from the verified authentication context.
- Domain mutation, immutable API audit, transactional Outbox intent, and successful idempotency completion commit or roll back together.
- School class/enrollment reads use a scoped transaction under the least-privilege runtime role.
- These three mutation routes no longer append to the realtime store or publish to the hub directly. The Outbox dispatcher is the only path from these mutations to realtime delivery.
- Publication occurs after commit. Delivery is at-least-once; the stable event ID and durable realtime append make replay/deduplication possible.

## Dispatcher
PostgresSchoolOutboxDispatcher claims rows from education_transactional_outbox with FOR UPDATE SKIP LOCKED, leases each claim, persists the realtime event, publishes to the in-process hub, and marks the Outbox row published. Failures are retried with exponential delay and eventually transition to DEAD.

The API process polls active tenant/organization scopes from education_actors. The polling loop is best-effort and never runs inside the school mutation transaction.

## Database deployment requirement
Migration 118_p056_1_school_api_runtime_grants.sql grants the runtime role only the audit insert and idempotency update operations needed by the UoW. Deployment must separately grant membership in tpay_school_runtime to the dedicated API database login. Do not use a superuser as the runtime login.
