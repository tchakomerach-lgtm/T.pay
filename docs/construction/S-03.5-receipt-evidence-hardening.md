## Threat gate
Assets: receipt history, contribution/payment/Ledger binding, provider reference and financial evidence.

Trust boundary: receipt data may cross mobile/offline/QR/client boundaries and therefore is untrusted outside the server-side persistence boundary.

Controls:
- replay/substitution: receipt ID + digest binding and database uniqueness;
- tampering: SHA-256 canonical digest + server HMAC;
- cross-receipt substitution: receipt ID is included in evidence and verified;
- data leakage: QR payload excludes amount, currency, provider reference and personal data;
- offline abuse: QR is evidence discovery only, never authorization/payment proof;
- secret theft: HMAC secret is server-side only;
- concurrency: DB uniqueness remains authoritative.

Safe failure: malformed, mismatched, stale or unauthenticated evidence is rejected; no Ledger mutation occurs.

## Remaining risks
- Current HMAC key rotation/versioning is deferred to the key-management brick.
- Existing legacy receipts are nullable during migration; they must not be presented as cryptographically verified evidence until backfilled.
- Full PostgreSQL receipt insertion should be extended in a subsequent integration patch so evidence columns are written atomically with the receipt row.
