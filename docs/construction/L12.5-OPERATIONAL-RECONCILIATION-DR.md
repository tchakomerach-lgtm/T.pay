# L12.5 — Operational reconciliation, DR failover and runbooks

L12.5 turns recovery evidence into executable operational controls. It never fabricates provider access, backups, failover success or regulatory readiness.

## African/Togo operating profile
- reconciliation queues remain usable during intermittent connectivity;
- provider outages create bounded retry/degraded states, never silent financial correction;
- field/offline backlogs expose age, volume and last successful sync;
- critical escalation supports internal queue/SMS through authorized routes;
- runbooks define owner, backup owner, trigger, maximum response window and evidence required.

## Exit gates
1. exact-head CI green;
2. PostgreSQL race/concurrency proof for reconciliation claims and DR state transitions;
3. durable reconciliation job/exception repository with tenant-safe idempotency;
4. tested failover state machine with explicit degraded mode and recovery verification;
5. operational runbooks and named owners/escalation windows;
6. dashboards covering reconciliation age, offline backlog, provider callbacks, recovery status and alert delivery;
7. backup/restore evidence linked to recovery records;
8. no claim of production-live DR until an authorized isolated drill proves it.

## Construction invariant
Financial Core remains the only financial truth. Reconciliation may quarantine, retry, escalate or request human correction; it must not invent compensating ledger entries automatically from ambiguous evidence.
