# L6.1 — Field Offline Security Boundary

## Scope
First brick of Layer 6. Adds the security contract for intermittent-connectivity field operations without creating a second financial ledger.

## Implemented
- Signed Ed25519 offline envelope verification.
- Organization/device/key binding.
- Device revocation boundary.
- Envelope freshness and clock-skew checks.
- Monotonic device sequence protection.
- Replay-claim contract.
- Sync conflict classification.
- Privacy-minimized field receipt evidence.
- Deterministic field-agent continuity/reassignment plan.

## Threat gate
Assets: payment/contribution intents, device identity, receipt evidence, organization boundary.
Threats: replay, cloned device, stale envelope, cross-organization injection, sequence rollback/gap, agent disappearance, malicious reassignment.
Controls: signature, device registry contract, org binding, freshness, monotonic sequence, durable replay contract, deterministic reassignment, no direct financial mutation.

## Tests
- Valid envelope accepted once.
- Cross-organization envelope rejected.
- Tampered ciphertext/signature rejected.
- Sequence gap/rewind rejected.
- Revoked device rejected.
- Expired envelope rejected.
- Receipt evidence excludes plaintext payload.
- Deterministic agent reassignment tested.
- No active agent produces no reassignment.

## External research
OWASP recommends explicit server-side state machines, rejection of replays, atomic handling of race-prone operations and idempotency for external side effects. PostgreSQL SERIALIZABLE transactions require application retry handling for SQLSTATE 40001. These principles remain authoritative for the later durable L6 persistence layer.

## Remaining risk
The replay store and device sequence store are currently interfaces, not yet PostgreSQL implementations. Therefore L6.1 is not production-complete and must not be described as the finished offline financial execution layer.
