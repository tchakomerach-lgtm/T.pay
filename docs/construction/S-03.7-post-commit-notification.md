# S-03.7 — Post-Commit Notification

## Threat gate
Assets: recipient identity, organization context, notification content and delivery state.

Controls:
- premature notification: derive from durable post-commit events;
- duplicate notification: unique (event, recipient, channel, template) intent identity;
- cross-organization leakage: organization_id is explicit and tenant-scoped;
- sensitive-data leakage: generic/sensitive classification and minimal notification contract;
- provider failure: durable retry state;
- worker takeover: claim owner required for completion;
- financial corruption: notification layer has no financial mutation API.

## External research
OWASP MASWE-0037 warns that notification surfaces can expose sensitive account, financial and authentication information; T.Pay therefore keeps sensitive details inside authenticated application views. NIST SP 800-61 Rev. 3 treats incident response as part of broader cybersecurity risk management, supporting durable operational state and recovery.

## Incident rule
Any material failure is a blocker until its root cause is resolved and regression coverage or an operational guardrail is added.

## Scope
- notification intent contract;
- durable PostgreSQL intent/claim schema;
- provider-independent post-commit delivery contract;
- negative tests;
- ADR-014.

## Remaining integration
A later adapter must connect durable outbox events to notification intent creation after commit, then connect approved SMS/email/push providers with provider-specific security contracts. No live provider credentials are introduced here.
