# P056.5 — Référentiel des matières

## Objet
Créer un référentiel académique par organisation, partagé par les classes, affectations et futurs contrôles d'évaluation. Le référentiel ne porte aucune donnée financière.

## Modèle PostgreSQL
- `education_subjects` : identifiant UUID, tenant, organisation, code, nom, description, coefficient, état actif, version, créateur et horodatages.
- Unicité du code par tenant et organisation.
- FK composite vers l'acteur créateur.
- RLS activée et forcée ; le rôle `tpay_school_runtime` ne reçoit que SELECT/INSERT/UPDATE.
- Pas de suppression physique : désactivation versionnée pour préserver les références historiques.

## API
- `GET /v1/education/subjects` : liste du référentiel de l'organisation ; filtre facultatif `active=true|false`.
- `POST /v1/education/subjects` : création idempotente.
- `PATCH /v1/education/subjects/{subjectCode}` : modification du nom, de la description, du coefficient ou de l'état avec `expectedVersion`.
- Permission : `org.read` en GET ; `org.manage` en écriture.
- Chaque mutation utilise le Unit of Work P056 : mutation + audit + Outbox + résultat d'idempotence dans une transaction PostgreSQL.
- Événement : `subject.changed`, publié uniquement par le dispatcher Outbox.

## Contrôles
- Codes normalisés en majuscules, format strict.
- Champs inconnus rejetés ; coefficient borné ; contrôle de version optimiste.
- Isolation tenant/organisation par RLS et contexte transactionnel.
- Aucun endpoint de suppression ; désactivation réversible et historisée par version.
- Une affectation ne peut référencer qu'une matière active du même tenant/organisation.

## Hors périmètre
Notes, évaluations, bulletins, frais, paiement, ledger et wallet. Les prochaines séquences les traiteront séparément. Les frais scolaires resteront des intents vers Financial Core.
