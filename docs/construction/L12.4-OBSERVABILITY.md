# L12.4 — Operational observability, SLO and alerting

This layer records operational evidence; it does not mutate Financial Core truth.

## Togo/Africa profile
- latency, queue depth, provider availability, callback lag, offline backlog and reconciliation age are measured as integer telemetry;
- SMS/internal-queue routes are first-class low-bandwidth escalation paths;
- correlation IDs survive degraded/offline operation and support later reconciliation;
- provider credentials never live in operational telemetry;
- SLO policies remain targets, never proof of achieved production performance;
- alert delivery is retriable evidence and cannot change ledger state.

## Implemented in this layer
- durable measurements, alert state and SLO policies;
- PostgreSQL concurrent alert-upsert proof;
- L12.3 incident-route selection by minimum severity;
- idempotent delivery evidence;
- provider/mobile-money degraded-mode drill evidence;
- stable dashboard views for latest telemetry, unresolved alerts and degraded dependencies.

## Dashboard metric contract
Production adapters must emit these stable metric families:
- `api.latency_ms`, `api.error_rate_bps`;
- `ledger_adjacent.queue_depth`, `ledger_adjacent.processing_lag_ms`;
- `provider.callback_lag_ms`, `provider.availability_bps`;
- `offline.backlog_count`, `offline.oldest_age_s`;
- `reconciliation.pending_count`, `reconciliation.oldest_age_s`.

A dashboard must distinguish **configured SLO**, **observed measurement**, **open alert** and **degraded dependency**.

## Operational ownership
Default escalation ownership (roles, not invented individuals):
1. **Platform/SRE owner** — API, queues, database and deployment health; acknowledge critical alerts within the production incident policy.
2. **Finance Operations owner** — Ledger-adjacent queues, reconciliation and provider settlement exceptions.
3. **Security owner** — security incidents, abuse signals and secret-rotation failures.
4. **Partner Operations owner** — mobile-money/MFI provider outage, callback lag and settlement degradation.
5. **Country Operations owner** — Togo field escalation, SMS/internal-queue fallback, agent/offline incidents.

Named individuals and phone numbers must be configured in the deployment environment before production activation; this document does not fabricate them.

## Exit gates
1. exact-head CI green;
2. PostgreSQL concurrent alert upsert/race test;
3. alert routing integration with L12.3 routes;
4. provider outage/degraded-mode drill;
5. dashboards for API, Ledger-adjacent queues, provider callbacks, offline backlog and reconciliation;
6. named operational owners and escalation windows.

Gates 1–5 are implemented/tested in the construction branch. Gate 6 remains an operational deployment gate until actual owners, contacts and escalation windows are configured. Therefore L12.4 is **not production-complete** on code alone.
